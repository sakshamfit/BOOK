# Orion Mall concept preview

This is a standalone preview, not a WordPress theme or a change to the live site. On wide screens, the hero can embed the user-provided YouTube video (`EaEdZmbsStI`), with a pause/play control. Phones, tablets, reduced-motion users and visitors with data saving enabled see the still-image fallback instead. The still also remains as a fallback if the embed is unavailable.

The footer is an Orion-specific, simplified React adaptation of the supplied Doodle Crew concept, in `components/ui/doodle-crew-footer.tsx`. Its internal navigation points to preview pages. It does not reproduce all features or props of the supplied component.

To rebuild the standalone preview footer after editing the component:

```sh
npm ci --prefix orion-preview
NODE_PATH="$PWD/orion-preview/node_modules" ./orion-preview/node_modules/.bin/esbuild orion-preview/footer-entry.tsx --bundle --minify --format=iife --outfile=orion-preview/footer.js --loader:.css=empty
python3 -m http.server 4173 --bind 0.0.0.0 --directory orion-preview
```

The repository already has shadcn configured with components in `components/ui`, global styles at `app/globals.css`, TypeScript, Tailwind, and React. The preview uses its own `style.css` and `footer.css` because it is a standalone static prototype, not the existing app.

The preview includes the main sections and category pages generated by `python3 orion-preview/create-pages.py`. These are design previews with selected highlights, not a complete WordPress content migration. Internal section links stay in the preview; directions, booking, phone, email and social links lead to external services. The same React footer mounts on every generated page.

## Site-wide motion and mobile layouts

Every preview page loads `site-experience.css` and deferred `site-experience.js`, after its existing styles/widgets. These are small, dependency-free progressive enhancements; no bundle step is required. Both page-generation templates include the same assets, and the static deployment builder copies them automatically.

- Scroll-triggered fade/slide reveals, staggered card entrances, restrained image zoom/card lift and animated navigation underlines use CSS opacity/translate transitions. An IntersectionObserver runs each entrance once. Entrance styles are then removed so they cannot delay normal hover effects. Dynamic footer/store cards are supported without observing per-frame style changes.
- Interactive clothing hangers, brand shelves, coffee physics and dialogs are excluded from shared transforms. All ten clothing pieces remain on their complete rack.
- Phones and tablets up to 1024px use a touch-friendly navigation panel with an animated menu icon, backdrop, scroll lock, inert background, keyboard focus containment, Escape and focus return. Closing or resizing restores the previous background state and scroll position. Navigation stays expanded and usable if JavaScript is unavailable or the enhancement script is blocked.
- Fluid headings, narrower-screen spacing, stacked category headings, single-column cards, readable movie facts, two-column footer links, 44px action targets, safe-area spacing and short-landscape layouts fix actual reflow rather than masking page overflow.
- A passive, frame-batched scroll handler updates the header shadow, a decorative progress line and a labelled back-to-top button. No perpetual site-level animation loop is used. Fashion autoplay pauses when offscreen, hovered, keyboard-focused, in a hidden tab or reduced-motion mode.
- `prefers-reduced-motion` is respected on load and when changed, with immediate visible content and no reveal transitions. Keyboard focus reveals pending content immediately. Without IntersectionObserver or JavaScript, all content remains visible. Hero video is never requested for narrow layouts, reduced motion or data-saving connections.

To check shared integration, responsive CSS and page regeneration:

```sh
npm run test:site-experience
npm run test:clothing-rail
npm run typecheck
npm run build --prefix orion-mall-site
```

Browser checks cover all 43 pages at 320px and the principal pages at 390, 768, 1024 and 1440px, plus touch/keyboard navigation, short landscape, live resizing, normal/reduced motion, blocked-script/no-JS fallbacks and the complete clothing rack.

## WordPress export content

The preview includes published pages, posts and events from the user-provided WordPress export. To refresh it, run `python3 orion-preview/create-pages.py` followed by `python3 orion-preview/import-wordpress.py /path/to/export.xml`. The importer uses the exported `content:encoded` fields and public media URLs, removes executable or embedded content, and rewrites known internal links. WordPress shortcodes, Elementor templates, plugin-generated content, forms, shop and booking functionality cannot be reproduced from this content alone and require a WordPress staging environment. The export is not included in this repository. The public site and media are unchanged.

To match explicitly associated Elementor category backgrounds and event featured media, also run `python3 orion-preview/place-media.py /path/to/export.xml` after the import. WordPress media files remain hosted by the existing site; this script does not upload or clone them.

The optional `add-elementor-media.py` script adds separate page-associated media galleries. These galleries were removed from the preview at the user’s request; do not run it unless they should be restored.

## Homepage arc carousel

The homepage brand feature uses a moving floor-by-floor directory instead of the earlier wheel. It includes 56 listings extracted from the available WordPress category pages, with hover and keyboard-focus pause, manual scrolling and a static reduced-motion mode. Select a brand for its category and floor. Some export listings have missing logos, inconsistent text or conflicting floors; these are labelled or use a name in place of a logo. Confirm the directory with mall management before publication. `build-brand-data.py` regenerates `data/brands.json` from the imported category pages, and will stop if their listing counts change so the curated names can be reviewed. The separate homepage photo feature uses `components/ui/photo-card-grid.tsx`.

The repository already has the shadcn UI directory, React, TypeScript and Tailwind configuration; the standalone preview uses `carousel.css` instead of Tailwind utilities. To rebuild the carousel after changes:


## Clothing store photo folders

The Clothing, Footwear, Cosmetic / Unisex Salon, Accessories, Chocolates, Fast Food, Restaurant and Fun Zone directories use `components/ui/glass-folder-cards.tsx`, an adaptation of the supplied glass-folder design. The brand name appears on the glass, and a logo appears underneath where one is known. Selecting the folder lifts the preview photos and opens the original photo gallery; selecting an exposed photo or thumbnail opens a photo-focused adaptation of the supplied Warp Carousel, with arrow and swipe navigation. It uses React alone and does not reproduce the supplied WebGL stat-card renderer. The original business details remain visible below. If a directory's listing count does not match its curated names in `data/brands.json`, enhancement is skipped to avoid mislabelling stores. Original content remains visible without JavaScript. Some source descriptions, images and floor information are inconsistent and should be reviewed before publication.

The repository already uses shadcn's `components/ui` path and `app/globals.css`, with React, TypeScript and Tailwind configured. The standalone preview uses `clothing-folders.css` rather than the main app's Tailwind styles. To rebuild after edits:

```sh
npm ci --prefix orion-preview
NODE_PATH="$PWD/orion-preview/node_modules" ./orion-preview/node_modules/.bin/esbuild orion-preview/clothing-folders-entry.tsx --bundle --minify --format=iife --outfile=orion-preview/clothing-folders.js
```

Regenerating pages can overwrite the folder script and stylesheet references and can restore removed sections; reapply these preview customisations after an import.

## Celebration imagery and brand shelves

The Valentine’s Week event uses `images/celebration-concept.jpg` as an explicitly labelled generated illustration, not a documentary photograph; its original event image remains in the event photo grid. Image-only groups on event pages are displayed in responsive grids. The homepage floor directory uses a brand-focused adaptation of the supplied product-shelf design in `components/ui/skincare-product-shelf.tsx`, rather than fictional products, prices or shopping-cart features. It retains the existing moving rows, hover/focus pause, reduced-motion behaviour and brand detail dialogs. This adaptation uses React only, so the supplied demo's `motion` and `lucide-react` dependencies are not required by the preview. The existing shadcn, Tailwind and TypeScript paths are documented above.

The homepage requests the locally installed Berlin Sans FB typeface. It is a licensed font and is not bundled with the preview; visitors who do not have it installed receive Nunito Sans as a web fallback. To use Berlin Sans FB consistently for all visitors, provide webfont files and a licence that permits web embedding.

## Clothing rail hero

`clothing.html` now replaces its old photo banner with the supplied interactive clothing-rail design. The reusable client component is `components/ui/product-rail-gallery.tsx`; `components/clothing-rail-hero.tsx` supplies the ten-piece Orion edit, and `clothing-rail-entry.tsx` mounts it above the existing directory. The Orion homepage (`index.html`) also shows the same rail after the fashion showcase and before the cinema section. Its mount uses `data-page="home"` to select an H2 heading and a CTA to `/clothing.html#clothing-stores`, keeping the homepage's original hero and H1 intact. The separate Folio Next.js homepage is not changed.

Every garment has an ORION wordmark on the right of its front-facing chest, including in the lift-out detail view. Both pages now use local **photorealistic clothing cutouts**, not the original SVG fabric illustrations. The garments show natural jersey, wool, fleece and twill texture, realistic folds and photographic wooden hangers. The small ORION mark is baked into the textile image so it turns with the garment, rather than floating as a separate logo. These are explicitly labelled AI-generated wardrobe concepts, not stock photographs, actual mall products or inventory claims. The CTA leads to the real clothing directory and its unchanged store photo folders.

The 18 optimised transparent WebPs in `images/clothing-rail/` share a 600 × 930 canvas and aligned hanger pivots. Their manifest maps all ten styles to their front views and eight available separate back views. The jacket and coat are front-only; the detail view intentionally offers no Back control for those pieces rather than passing off a duplicate front as a back. Only fronts load on the rail; backs load when a detail is opened. The generic SVG renderer remains available as a fallback API but is not used for this edit.

The repository already provides shadcn (`components.json`, `@/components/ui`), TypeScript, React, React DOM, Tailwind CSS 4 and Lucide. No new runtime dependencies or context providers were added; all interaction state is local. The app's default stylesheet remains `app/globals.css`. Since this page is a standalone HTML preview, its Tailwind source is `clothing-rail.input.css`, compiled to the checked-in `clothing-rail.css`. The build scopes utilities and theme variables to the rail and its portal so the header, store folders and footer keep their existing styles. Use Lucide for controls. The cutouts include their own physical-looking hangers, so this edit passes `hanger="none"`; no synthetic hanger or numbered price tag is added.

Rebuild and test after editing the component or edit data (install the existing root dependencies first with the repository's normal `npm run install:ci` if needed):

```sh
npm ci --prefix orion-preview
npm run build:clothing-rail
npm run test:clothing-rail
npm run typecheck
python3 -m http.server 4173 --bind 0.0.0.0 --directory orion-preview
# Open / or /clothing.html
```

The committed cutouts do not need regeneration to build or deploy. For image-authoring changes, `prepare-clothing-photos.py` uses Pillow and NumPy to chroma-key the generated source portraits, align their canvases, recolour the edit, add the chest embroidery and save optimised WebPs. Source PNGs stay in ignored `work/clothing-rail/`, not in Git. To run that optional authoring step with those source files available:

```sh
python3 -m pip install --target work/python-imaging pillow numpy
PYTHONPATH=work/python-imaging python3 orion-preview/prepare-clothing-photos.py
npm run build:clothing-rail
```

Both pages keep **all ten garments on one complete, ordered rail at every screen width**, rather than switching to a cropped three-item carousel. `lib/clothing-rail-layout.ts` fits the entire rack, reserving room for a selected front-facing piece. Compact layouts turn the other hangers farther edge-on while keeping every piece visible. Each garment pivots at its hook on the metal bar, with footprint-sized hit targets so transparent image canvases cannot intercept adjacent hangers. Resize updates the whole rack in place.

Wide-screen visitors can hover to turn and click to lift. On compact/touch layouts, tap once to select and again to lift; swipes and the labelled Previous/Next buttons change the selection without moving pieces off the bar. The controls show the full collection count. Keyboard controls are Left/Right, Home/End and Enter; the detail view supports Front/Back where available, dragging to turn, Escape, trapped focus and return focus. Autoplay has a pause/play control, stops on interaction, and pauses offscreen/in hidden tabs; reduced-motion users get immediate transitions with no autoplay. A heading and working directory link remain if JavaScript is unavailable. `create-pages.py` preserves this hero replacement and anchor when regenerating the clothing page; other preview customisations still need the existing regeneration care described above.

The rail tests cover full-rack geometry for every selected hanger from 240px through 1440px stage widths, including mixed-width garments and larger collections, in addition to photo assets, branding, page integration, CSS scoping and regeneration.
